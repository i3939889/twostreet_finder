# TwoStreet Finder 規格文件

## 1. 目標

使用 Playwright 開發一個針對 [2nd STREET 台灣官網](https://store.2ndstreet.com.tw/) 的商品爬蟲。

程式需依照 `.env` 中指定的主分類、次分類與分店名稱，自動篩選符合條件的商品，並輸出成 JSON。

## 2. 設計範圍

- `MAIN_CAT` 只允許單一值
- `SUB_CAT` 可為多個值，以逗號分隔
- `STORE_NAME` 可為多個值，以逗號分隔
- 每次執行只處理一個主分類
- 在同一個主分類下，依序處理多個次分類

## 3. 輸入規格

程式需從 `.env` 讀取以下欄位：

### 3.1 MAIN_CAT

- 型別：字串
- 規則：只允許一個值，不可使用逗號分隔多值
- 說明：要展開的主分類名稱
- 範例：`服裝`

### 3.2 SUB_CAT

- 型別：字串
- 規則：可包含一個或多個值，以逗號分隔
- 說明：要依序點選的次分類名稱
- 範例：`短袖T恤,牛仔褲,帽T`

### 3.3 STORE_NAME

- 型別：字串
- 規則：可包含一個或多個值，以逗號分隔
- 說明：商品標題比對用的分店名稱
- 範例：`台北西門店,台中一中店`

## 4. 設定驗證規格

程式啟動後需先驗證設定：

- 必須成功讀取 `.env`
- `MAIN_CAT` 不可缺失
- `SUB_CAT` 不可缺失
- `STORE_NAME` 不可缺失
- `MAIN_CAT` 去除前後空白後不可為空字串
- `SUB_CAT` 切分後至少需有一個有效值
- `STORE_NAME` 切分後至少需有一個有效值
- 若 `MAIN_CAT` 含逗號，視為格式錯誤並直接停止

建議前處理邏輯：

- `MAIN_CAT`：`trim()` 後作為單一字串使用
- `SUB_CAT`：以逗號切分、逐項 `trim()`、過濾空字串
- `STORE_NAME`：以逗號切分、逐項 `trim()`、過濾空字串

## 5. 執行流程

1. 啟動 Playwright 瀏覽器。
2. 開啟首頁 `https://store.2ndstreet.com.tw/`。
3. 等待首頁主要導覽列載入完成。
4. 將滑鼠移到上方選單中的「商品分類」。
5. 等待商品分類選單展開。
6. 在選單中找到 `MAIN_CAT`。
7. 點擊 `MAIN_CAT` 右側箭頭，展開其對應的次分類清單。
8. 依序處理每一個 `SUB_CAT`：
9. 在次分類清單中點擊該 `SUB_CAT`。
10. 等待商品列表頁更新完成。
11. 擷取當前頁面已載入的商品資料。
12. 檢查商品標題是否以任一個 `STORE_NAME` 開頭。
13. 保留符合條件的商品。
14. 持續向下捲動頁面，等待更多商品載入。
15. 重複商品擷取與過濾，直到頁面底部且沒有新商品出現。
16. 切換到下一個 `SUB_CAT`，重複相同步驟。
17. 合併所有符合條件的商品資料。
18. 輸出 JSON 檔案。
19. 結束程式。

## 6. 商品篩選規格

商品必須同時符合以下條件才算命中：

- 商品位於指定 `MAIN_CAT` 之下的某個 `SUB_CAT` 頁面
- 商品標題以任一個 `STORE_NAME` 開頭

建議判定方式：

- 先對商品標題做前後空白清理
- 使用 `startsWith(storeName)` 進行比對

例如：

- `STORE_NAME=台北西門店,台中一中店`
- 商品標題為 `台北西門店 NIKE 短袖T恤`

則該商品應被保留，並記錄命中的 `storeName` 為 `台北西門店`

## 7. 商品資料欄位

每筆輸出資料至少需包含以下欄位：

- `title`：商品標題
- `url`：商品連結
- `storeName`：命中的分店名稱
- `mainCategory`：主分類
- `subCategory`：次分類

若頁面可穩定取得，建議額外收集：

- `price`：價格
- `imageUrl`：商品圖片網址
- `productId`：商品唯一識別碼
- `scrapedAt`：爬取時間，ISO 8601 格式

## 8. 輸出規格

- 輸出格式：JSON
- 建議輸出路徑：`output/results.json`
- 資料格式：陣列
- 編碼：UTF-8

範例：

```json
[
  {
    "title": "台北西門店 NIKE 短袖T恤",
    "url": "https://store.2ndstreet.com.tw/goods/xxxxx",
    "storeName": "台北西門店",
    "mainCategory": "服裝",
    "subCategory": "短袖T恤",
    "price": "NT$990",
    "imageUrl": "https://example.com/image.jpg",
    "scrapedAt": "2026-03-18T10:00:00.000Z"
  }
]
```

## 9. 去重規格

為避免同一商品在捲動過程中被重複擷取，程式需具備去重邏輯。

建議規則：

- 優先使用 `url` 作為唯一鍵
- 若 `url` 無法穩定取得，再以 `title + price` 作為備援鍵

## 10. 捲動終止條件

捲動過程在符合以下任一條件時停止：

- 已捲到頁面底部，且頁面高度不再增加
- 連續多次捲動後，商品總數未再增加
- 頁面出現明確的無更多商品提示

建議初版策略：

- 每次捲動後等待頁面載入
- 若連續 3 次捲動後商品數量都沒有增加，視為完成

## 11. 錯誤處理規格

程式需處理以下錯誤情境：

- `.env` 缺失
- `.env` 欄位缺失或格式錯誤
- 找不到指定 `MAIN_CAT`
- 找不到指定 `SUB_CAT`
- 頁面載入逾時
- 商品列表結構與預期不符
- 捲動後無法再正確擷取商品

建議策略：

- 設定錯誤時直接停止
- 單一 `SUB_CAT` 失敗時記錄錯誤並繼續處理下一個 `SUB_CAT`
- 最終輸出除商品資料外，也可附帶錯誤摘要供後續排查

## 12. 非功能性規格

- 使用 Playwright 實作
- 支援 headless 與 headed 模式切換
- 優先使用穩定的文字、角色或結構型 selector
- 避免過度依賴容易變動的 CSS class
- 等待策略應以 `waitForSelector`、`locator` 狀態或內容變化為主
- 不建議只依賴固定秒數的 `sleep`

## 13. 建議模組切分

- `config`：讀取與驗證 `.env`
- `navigator`：處理首頁導覽、主分類與次分類切換
- `scraper`：擷取商品資料與欄位整理
- `filter`：依 `STORE_NAME` 過濾商品
- `scroller`：控制捲動與停止條件
- `writer`：輸出 JSON
- `logger`：記錄執行過程與錯誤

## 14. 實作假設

目前先採用以下假設：

- 「登入首頁」的意思是進入首頁，不包含會員帳號登入
- 商品標題格式穩定，可用分店名稱前綴判定
- 不同 `SUB_CAT` 的結果可直接合併輸出
- 若同一商品出現在多個次分類中，最終仍以去重邏輯保留單筆資料

## 15. 後續實作建議

建議先完成以下順序：

1. 建立 `.env` 讀取與驗證
2. 確認網站導覽列與分類選單的實際 selector 策略
3. 實作單一 `SUB_CAT` 的導頁與商品抓取
4. 加入多個 `SUB_CAT` 迴圈
5. 加入捲動、去重與輸出 JSON
6. 最後補上錯誤處理與執行紀錄
